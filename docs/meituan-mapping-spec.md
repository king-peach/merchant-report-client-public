## 3. 网页抓取部分（脑图原文）

- 门店选择：**运营报表 Sheet 名 = 唯一关键字**（Sheet 名匹配门店）
- **主站流量**：经营分析 → 经营数据 → 流量 → 自定义选对应日期 → 全部下拉菜单选「外卖」→ 商圈同行均值/商圈同行前 10% 均值 → 全部顾客 / 新客 / 老客
- **拼好饭流量**：同上，下拉菜单选「拼好饭」→ 商圈同行均值/前 10% 均值 → 全部顾客 / 新客 / 老客
- **推广曝光量 CF**：经营分析 → 经营数据 → 推广 → 昨日 → 数据源下所有选项的总曝光次数之和
- **推广曝光量 CG**：同上（第二个数据源）
- **推广消耗金额 CE**：门店推广 → 消费记录 → 进入推广财务对账页 → 推广流水记录 → 自定义选对应日期 → 推广订单扣款 + 推广消耗金额
- **充值金额 CJ**：推广账户自动充值 + 推广充值金额

## 4. 实测补充（2026-09-18 落地验证）

- **★流量列不爬页面——报表自带**（决定性实测发现）：
  83 列全部业务报表 **X~AN** 含 曝光/入店/下单人数+转化率 + 新老客拆分（曝光新客/入店新客/
  新客入店转化率/新客下单转化率/曝光老客/入店老客/老客入店转化率/老客下单转化率/曝光次数/入店次数/
  下单人数/下单新客/下单老客）；拼好饭 31 列报表 **O~AE** 同构。与流量页数据同源
  （09-17 全部门店曝光 48053 = 流量页一致）。
  → `meituan_mapping.TRAFFIC_MAPPING` 据此填 L/O/R/U/X、AA/AD/AG、AJ/AM/AP（主站）与
  AX/BA/BD/BG/BJ、BM/BP/BS、BV/BY/CB（拼好饭），离线校验 44/44 一致。
- **商圈TOP列 PC 端无数据源**（重要负结论）：流量页/总览页/报表中心全文与全部 POST 接口
  均无 商圈/同行 流量对比；`circle` 字段只挂营收类指标（营收 tab 有商圈均值）。
  脑图「商圈同行均值/前10%」口径来自手机 App 端。**当前 TOP 列留空**（用户确认方案 A），
  差异公式会显示负的本店值 = 诚实的「TOP 无数据」信号。
- **两份报表都自带流量列**（本店值无需抓取）：
  - 全部业务（83 列）：曝光人数 / 入店人数 / 下单人数 等
  - 拼好饭（31 列）：O–AE 曝光/入店/下单 + 新老客拆分
  - 只有**商圈 TOP 列**必须抓取；**差异列是公式，永不写静态值**
- **下载流程实现要点**：生成必须走 UI（裸 fetch 直调报 `code:500 服务器开小差了`）；**每个业务都重新加载报表页**——
  切 tab 后上一业务的指标勾选仍在，带着「全部」的 111 个选点去下拼好饭，会拿到与全部业务逐字节相同的文件。
- **行序**：top 模式（插入新行）内**按日期升序写入**，最新一天才落在表头下第一行。
- 全店聚合（scope=all）只对**可加列**求和（营业额/营业收入/订单量/补贴/取消单），得分与率类列留空不臆造。
