# 商家运营报表自动化客户端 · 需求规格说明书

**版本**: v0.1（待评审） · **日期**: 2026-09-16 · **来源**: taobao-shangou-report skill 产品化

---

## 1. 项目概述

### 1.1 一句话定位
面向餐饮/零售商家（首批客户：茶饮加盟门店运营者，Windows PC）的**桌面客户端**：一键完成各外卖平台经营数据的下载、抓取、汇总填表，并接入大模型提供经营解读与异常自愈。

### 1.2 核心价值
| 现状（skill 手动/半自动） | 客户端目标 |
|---|---|
| 需要会话式驱动（对话里跑脚本） | 双击图标 → 点一个按钮出报表 |
| 报表下载、网页抓取分步执行 | 一键全流程，进度可视化 |
| 出错时人工排查 | LLM 辅助诊断 + 人工操作提醒 |
| 单平台（淘宝闪购） | 三平台（淘宝闪购/美团/京东）适配器架构 |
| 单店 | 品牌-多门店管理 |

### 1.3 用户画像
- **主用户**: 门店运营/店长，Windows 10/11，非技术（不会命令行/配置文件）
- **环境假设**: 可安装桌面软件；有 Chrome 或允许客户端自带浏览器内核；能扫码/输账号密码登录各平台后台
- **关键约束**: 商家后台有滑块验证/风控，**登录环节必须保留人工**（合规红线，不做验证码破解）

## 2. 技术选型（推荐方案）

### 2.1 架构：Tauri 2.0 壳 + Python 任务内核（v0.3 定案）
```
┌─────────────────────────────────────────────┐
│  桌面壳: 路线A=本地HTTP+浏览器  路线B=Tauri(WebView2) │
├─────────────────────────────────────────────┤
│  任务内核 (Python, 每任务独立子进程 py_runner 模式) │
│  ├── 编排器: 下载→抓取→填表→LLM解读            │
│  ├── 淘宝/美团/京东 适配器                     │
│  └── openpyxl 填表 / 天气 / LLM 客户端          │
├─────────────────────────────────────────────┤
│  浏览器自动化: Playwright 驱动【系统浏览器】     │
│  回退链: msedge(预装) → chrome → 引导装Chromium  │
│  持久 profile 目录存登录态(登录一次后续免登)      │
├─────────────────────────────────────────────┤
│  数据层: SQLite + 文件（模板/报表归档）           │
└─────────────────────────────────────────────┘
```

**浏览器决策（v0.2 变更）**: 不打包 Chromium。Edge 是 Win10/11 预装（Chromium 内核），`playwright channel="msedge"` 直接驱动，安装包 -150MB+。Playwright 本体（含 driver ~40MB）保留；裸 CDP+websocket（~1MB）作为极限瘦身备选，v1 不做。

**选型理由**:
- ✅ **任务内核 Python**: 现有自动化代码零重写；LLM 走云端 API，本地无 GPU 需求
- ✅ **系统浏览器驱动**: Edge 预装率 ~100%（Win10/11），客户零安装步骤；登录态存独立 profile 目录，不污染客户日常浏览器配置
- 双轨壳选型见 2.3

### 2.2 LLM 接入
- **协议**: OpenAI 兼容 `/v1/chat/completions`（GLM/DeepSeek/通义/Kimi/豆包均支持），客户端设置页可配 Base URL + Key + 模型（沿用教师工作台的「预设下拉 + 测试连接真实调用」设计，**必须真调验证**，防假阳性）
- **默认模型策略**: 文本任务用国产旗舰便宜档（GLM-4.7-flash / DeepSeek-V3.2 级别），不需要视觉（自动化全走 DOM 不走截图判读）
- **三大用途**（优先级 P1 > P2 > P3）:
  - **P1 经营日报解读**: 报表填完后，LLM 按固定框架生成本店 vs 商圈TOP10 差距分析 + 3 条可执行建议，展示在客户端日报页 + 可推送微信/飞书
  - **P2 异常自愈助手（安全收窄，v0.2 修订）**: 自动化某步失败时，LLM 拿到「页面文本片段 + 失败选择器」输出**修复建议（新选择器/参数补丁）**，**经用户确认后应用**；只开放选择器/参数级白名单修改，**不做 LLM 动态生成任意代码执行**；连续失败自动降级人工模式
  - **P3 对话式问答**: 客户端输入框问"昨天为什么单量掉了"，LLM 基于当日+历史数据回答（带数据引用，不编造）
- **边界（铁律）**: LLM **不参与**数据计算/填表，核心流水线是确定性代码（可回归测试、行为可复现）；LLM 不可用时全流程功能不受影响

### 2.3 壳方案: Tauri 2.0 + python-embed（v0.3 定案，用户拍板）

**决策依据（用户三理由 → 落地机制）**:
- **界面可定制/好看** → Tauri 窗口 + React/TS 全权定制 UI，WebView2 渲染（Win10/11 预装 evergreen，无需分发浏览器内核）
- **与 LLM 更适配** → ①Tauri 事件系统把任务进度与 LLM 流式输出（token 级）原生桥接到前端（对比路线 A 的 HTTP 轮询体验）②LLM 调用仍收在 Python 内核（单一实现处），壳只做事件转发
- **性能更好** → 无 Node 运行时；壳内存占用小；重活（浏览器自动化）本就在独立 Python 子进程，壳层轻

**体积诚实账（v0.3 修正）**:
| 组件 | 体积 |
|---|---|
| Tauri exe + WebView2 loader | ~8-10MB |
| python-embed 3.12（微软签名链，杀软友好） | ~15MB |
| site-packages: playwright（含 node driver **~35MB，不可压缩**）+ openpyxl + certifi 等 | ~50MB |
| **合计（NSIS 压缩后安装包）** | **≈45-55MB**（不是 25-35MB，driver 是大头） |
| **后续瘦身路径** | 自动化 CDP 调用移植进 Rust（chromiumoxide crate 替代 playwright）→ 砍掉 driver+python 浏览器层 → **~20-25MB**；v2 再做（重写自动化层风险大，v1 不动） |

**工程要点**:
- `src-tauri/resources/python-embed/`（嵌入版 Python）+ 构建期 `pip --target` 预装依赖；`tauri.conf.json` bundle.resources 打包
- **py_runner 模式（Task Command）**: Rust `spawn` python 任务子进程（独立临时工作目录）→ 逐行收 **NDJSON 事件流**（协议见 docs/任务协议-NDJSON.md）→ `emit` 转发前端；捕获 exit_code；产物（xlsx）落数据目录
- **脚本热更新**: 自动化代码是 resources 下的 .py 文件（非冻结二进制）→ 平台改版只替换 .py 即可生效，支持后续做在线更新通道（外卖后台月月改版的高频刚需）
- 杀软误报: python-embed（微软签名）+ 无 PyInstaller 加壳 → 显著低于路线 A；代码签名证书仍建议加购

**边界（沿用 v0.2 铁律）**: 核心流水线是确定性 Python 代码（不 CodeAct 化）；LLM 只做日报解读与「建议+确认制」的选择器级自愈；py_runner 的隔离目录不等于安全边界——任务代码白名单化，客户机登录态/经营数据不暴露给动态生成代码

## 3. 功能需求

### F1 门店与账号管理（P0）
- F1.1 门店 CRUD：名称/平台门店ID/所属品牌/模板文件路径/经纬度（天气用）；支持从配置文件导入
- F1.2 多门店列表页：每店显示最近一次成功运行时间与状态
- F1.3 平台账号：每平台可存用户名（密码建议系统凭据管理器/ENV 注入，不落明文 SQLite；v1 可先明文+提示风险，文档说明）
- F1.4 登录状态检测：显示各平台「已登录/未登录/待验证」徽标

### F2 一键日报（P0，核心流程）
- F2.1 触发方式：①首页大按钮（选门店+日期，默认昨天）②定时自动（F5）③命令行（高级）
- F2.2 流程编排（复用 runner 逻辑）:
  1. 登录检查 → 未登录转 F3
  2. 报表下载：淘宝闪购（全部+爆品团两份任务，下载管理轮询落盘）
  3. 网页抓取：流量页 6 态（外卖/爆品团 × 全客/新/老，基准=前10%均值）+ 推广页（昨日）
  4. 天气获取：2345 历史 API（天气现象）+ Open-Meteo 逐小时按营业时段窗口统计温度
  5. 填表：插入新行到第一行（最新在顶部）/ 公式列保护（54 列不写静态值）/ 全区公式引用平移 / 整行边框 / 回读验证
  6. LLM 日报解读（可开关）
- F2.3 **进度可视化**: 每一步实时状态条（进行中/成功/跳过/失败+原因），失败步骤标红并可「重试此步」
- F2.4 结果页: 报表文件入口（打开所在文件夹）+ 数据摘要卡片（营业额/订单/曝光/TOP差距）+ LLM 点评
- F2.5 交叉校验展示: 营业额=主站+爆品团 等校验结果列表，校验失败醒目告警

### F3 登录与人工操作提醒（P0，用户体验核心）
- F3.1 登录流程: 客户端弹出可见浏览器窗口（Playwright headed）→ 自动填已保存的账号密码（如有）→ **检测到滑块/验证码时，客户端同时弹出提醒** → 人在浏览器完成 → 客户端自动检测登录成功并继续（轮询逻辑已有）
- F3.2 **提醒通道**（多层兜底）:
  - Windows 系统通知（toasts，带声音）
  - 客户端窗口内横幅 + 任务按钮闪烁
  - 浏览器窗口自动置顶
  - （可选）微信/飞书 webhook 推送
- F3.3 提醒场景枚举:
  | 场景 | 提醒文案要点 | 超时策略 |
  |---|---|---|
  | 需要登录/滑块验证 | "请在弹出的浏览器中完成验证，完成后自动继续" | 等待 5 分钟，超时挂起任务并通知 |
  | 下载任务长时间未生成 | "后台报表生成较慢，已等待 X 秒" | 4 分钟转人工指引（打开下载管理页指引） |
  | 找不到页面元素（疑似改版） | "页面结构可能已变化，AI 正在分析…" → LLM 诊断结果 | 降级人工模式 |
  | 交叉校验失败 | "数据校验未通过：营业额≠主站+爆品团，请核对" | 人工确认后可强制继续 |
  | 模板文件缺失/被占用 | "模板文件被 Excel 占用，请关闭后重试" | 阻塞重试 |
- F3.4 提醒历史页：所有提醒留痕可回看

### F4 模板管理（P0）
- F4.1 模板上传/更换（每店一个 xlsx），客户端做**模板健康检查**: 公式列扫描（自动识别哪些列是公式不写入）、表头结构校验、A列日期格式检查
- F4.2 填表设置: 模式（最新在顶部插入/按日期匹配）、是否加边框、跳过公式列清单可视化确认
- F4.3 产物管理: 历史产出文件按 门店/日期 归档，可打开/备份到网盘目录

### F5 定时任务（P1）
- F5.1 客户端可最小化到系统托盘常驻，内置调度器（每日 HH:MM 对启用的门店自动跑 F2 全流程）
- F5.2 错过补偿: 电脑当时关机 → 开机后检测昨日未跑，提醒补跑（不自动跑，等确认——避免早上电脑刚开机登录态异常）
- F5.3 运行日志：每次任务完整日志（含每步耗时），可导出

### F6 多平台适配器（P1 起步，架构 P0 就位）
- F6.1 适配器接口: `login() / download_reports(date) / fetch_funnel(date) / fetch_promo(date)` 四方法，平台实现各自封装（淘宝闪购实现=现有代码）
- F6.2 **美团**（脑图步骤已在档）: waimai.meituan.com 报表下载（全部业务+拼好饭两份）+ 经营分析流量页（含商圈前10%口径）+ 推广消费记录——需真实账号实测后开发，预估 2-3 天/平台
- F6.3 **京东**: store.jddj.com 经营罗盘报表下载——同上
- F6.4 模板映射配置化: 每平台×每模板的字段映射表（列号←数据源）做成可编辑 JSON，新增模板不用改代码

### F7 设置页（P0）
- LLM 配置（预设下拉+自定义+测试连接）、提醒方式开关、下载目录、开机自启、主题；**全部界面化**（下沉客户铁律：不碰配置文件）

### F8 数据增强（P2，可砍）
- 经营趋势图表（营业额/曝光 30 日曲线 + TOP 对比雷达图）
- 多店对比视图（品牌主用）

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| **打包** | Tauri 2.0 NSIS 安装包 ≈45-55MB（含 python-embed + playwright driver）；**不打包浏览器内核**，驱动系统 Edge/Chrome（回退链）；必打 certifi |
| **Windows 兼容** | Win10/11 x64；杀软误报应对（PyInstaller 众所周知问题）：提交微软误报申诉 + 文档说明；安装免管理员权限 |

| **升级** | 检查更新接口 + 下载新 exe 替换（配置/数据目录在 %APPDATA%，升级不丢） |
| **合规** | 不做验证码破解/风控绕过；登录永远人工完成；遵守平台 robots 与账号协议 |

## 7. 里程碑（Tauri 路线）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M1 内核移植**（~3天，纯 Python 可先行） | 现有脚本模块化重构 + 任务编排器 + **NDJSON 事件流输出**（壳无关，可先用 CLI 消费验证） | CLI 跑通全流程，事件流完整 |
| **M2 Tauri 壳**（~4天） | Rust: py_runner(NDJSON→emit)/托盘/通知；前端 React 7 页 + 进度可视化 | 双击安装包完成一次日报全流程 |
| **M3 打包交付**（~2天） | python-embed + pip --target + tauri bundle + Win10/11 实机 + 安装引导文档（含 Edge 首启授权页） | 客户机器双击可用 |
| **M4 LLM 层**（~2天） | 日报解读（流式到前端）/ 异常自愈（建议+确认制）/ 问答 | LLM 挂掉不影响核心流程 |
| **M5 多平台**（每平台2-3天） | 美团→京东适配器 + 映射配置化（改 .py 热生效） | 需客户提供各平台测试账号 |

**风险预告（Tauri 首次踩坑点，M2 预留 buffer）**: Rust 侧 sidecar 生命周期管理、WebView2 版本差异、NSIS 中文路径、python-embed 缺 ssl 模块需单独补 DLL——都在 M2/M3 内消化。

## 8. 风险与开放问题（需拍板）

1. **~~浏览器内核分发~~（v0.2 已决）**: 驱动系统 Edge（Win10/11 预装）→ Chrome → 引导装 Chromium 的回退链，不打包内核
2. **杀软误报**: 无代码签名证书时 Windows Defender/360 可能拦；建议加购代码签名证书（约 ¥600-1500/年）或先观察
3. **登录态稳定性**: 淘宝系登录态有效期不定，隔天失效概率存在——客户端必须有「一键重新登录」顺滑体验（已设计）
4. **美团/京东的反爬强度未知**: 淘宝闪购已验证可自动化，美团风控更严，需实测（M5 前置条件：客户提供账号）
5. **收费形态与交付**: 单机授权（license 绑机器码）？影响是否做 license 模块（M3 可后补）
6. **模板版本演进**: 客户改模板结构 → 公式列扫描自动适配，但列映射（DG←营业额等）需重配——映射配置化在 F6.4，v1 淘宝模板固定写死即可
